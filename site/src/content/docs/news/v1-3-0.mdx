## Commands for state only Twill can see

The console could reach players and their data, but not Twill itself: which
services booted, which remotes nothing serves, what a replicated key holds, or
what log level a live server runs at. Twill now ships commands for that state,
and no gameplay commands. Commands such as `fly` or `speed` depend on your own
character rules, so they stay in your game.

| Command | What it does |
| :--- | :--- |
| `twill` | Shows boot order, declared remotes and whether anything serves them, the data store, and replication counts. A remote marked `UNSERVED` was never given to [`Net.Handle`](/reference/net/). |
| `loglevel` | Reads or sets the [log level](/reference/log/) on a running server, without republishing. |
| `repl` | Reads [replicated state](/reference/replication/), and freezes, unfreezes or throttles a key. |
| `rank` | Reads a player's rank, or overrides it for the session. |
| `pass` | Checks game pass ownership, and clears the cached answer. |
| `saveall` | Asks every open data session on the server to write. |
| `verifyroll` | Checks a revealed seed against the commitment a [round](/reference/random/) published before the draw. |

`verifyroll` lets a moderator settle a disputed roll in front of the player,
without either side having to trust the other.

## `rank` cannot hand out authority

`rank set` refuses three things:

- Changing your own rank.
- Changing the rank of anyone at your rank or above.
- Granting a rank at or above your own.

The most a moderator can create is someone strictly below themselves. The test
suite asserts all three refusals.

## Choose which commands register

`Admin.Configure` takes `TwillCommands`, in the same three shapes as
`DefaultCommands`:

```luau
Twill.Admin.Configure({
	MinimumRank = Ranks.Moderator,
	TwillCommands = { "twill", "loglevel" },
})
```

A command left out is never registered and never moved into
`ReplicatedStorage`, so it is absent from the client rather than hidden there.

## Security fix

`moderation` ran its rank check before `kick` and `ban`, but not before `unban`.
Anyone who could reach the console could lift a ban placed by someone ranked
above them. `unban` now answers to the same check.

## Other changes

- The header of `moderationServer` no longer claims to refuse a moderator acting
  on an equal. It can compare ranks only for a target on the same server, as the
  [troubleshooting reference](/reference/troubleshooting/) already said.
