## A bag for a subscription

[`Replication.Subscribe`](/reference/replication/) takes an optional third
argument, which is the argument every other Twill function that opens a lasting
connection already took.

```luau
Replication.Subscribe("Data.Coins", function(coins)
	label.Text = Twill.Format.Comma(coins or 0)
end, trove)
```

That is not only tidier. A subscription made for one player and never bagged
outlived them, and went on firing into a closure holding the whole interface it
was drawing into. Passing a bag ends it with the player. Passing none behaves
exactly as it did before, so nothing already written has to change.

## Two defects

**`Schema` threw on a rule it promised to refuse.** An `"object"` rule naming no
fields iterated over `nil`. Every other rule form already answered `false` for a
malformed rule, which is what the module says it does. This one sat on the path
that screens the arguments of every remote served by `Net.Handle`.

**`Lifecycle` announced departures it had never announced arrivals for.** A
player who left while the data gate still held them reached no service at all,
and yet every service was told they were leaving.

The second is worth dwelling on. Both [Services](/core-guides/services/) and
[Architecture](/explanation/architecture/) have described the correct behaviour
since v1.0.0. The documentation was right and the code was wrong, for ten
months, because nobody read them side by side.

## Documentation

Every module now opens the same way: what it is, what it does as a list, and a
note only where one earns its place. Reasoning that used to sit in comments
inside function bodies moved to where a reader looks for it.

Reading the two against each other turned up more than the `Lifecycle` defect.
Three pages claimed Twill has no request path, which is true of `Replication`
and of nothing else. `Net.Declare` has taken reply types since v1.0.0, and a
remote that replies is metered, ranked, and screened like any other. What is
refused is the pull, not the question.

`Monetization` kept the last fifty granted purchase ids and said so nowhere,
while its page stated the idempotency guarantee with no bound at all. The bound
is written down now, along with how far it sits from where redelivery happens.

And the framework stopped describing who it is for. Installing is two folders,
no build step, no package manager; every require resolves against the DataModel,
so nothing changes whether a place was built by hand, synced from files, or
generated by tooling of your own.
