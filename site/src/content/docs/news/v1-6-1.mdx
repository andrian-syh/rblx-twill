## A string built for an error that never came

`Net.Any` built a path string for every key of every table it wrote. The string
existed for one purpose: to name a value if something went wrong with it. It was
built on the way through regardless, so the overwhelming majority of them were
assembled, held, and discarded without ever being read.

Paths are now composed where the error is raised, and once per container rather
than once per key.

This is not an even saving across the module.
[`Replication`](/reference/replication/) sends its patches through `Any`, so of
everything the codec touches, this is the path that carries the most.

## An error that would not name the key

A numeric key inside a dictionary used to be reported without saying which key
it was. The message named the container and then gave up at the point it
mattered.

```text
before:  value[?]
after:   value[7]
```

Nothing about the encoding changed. The path is built at the point where the key
is still in hand.

## Two thousand checks for one guarantee

An array of fixed-width numbers checked the buffer's capacity once for the whole
run, and then checked it again for every element in that run. The first check
had already covered all of them.

The run is now written and read through the offset that single check returned,
so a two thousand element array costs two thousand fewer bounds checks in each
direction.

**Nothing is checked less.** The one check still covers the whole run before a
byte is touched. What went away is the repetition behind it, not the guarantee.

## Tables that existed for one loop

Packing and unpacking a `CFrameRot` allocated a table per value on the way out
and two on the way back. They use locals now.

`Any` was worse: it allocated a twelve element table for every `CFrame` it
wrote, purely to iterate the components it had already unpacked. It writes them
directly.

Neither changes the wire format. A place running v1.6.0 and a place running
v1.6.1 produce the same bytes.
